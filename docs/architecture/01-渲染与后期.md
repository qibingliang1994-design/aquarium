- 自动画质 v2（v2.1）：`src/systems/quality.js` 纯状态机（有单测）——5 档阶梯
  （高清 → 1.5 → 1.25 → 1+低配玻璃 → 关泛光），每 0.5 秒按**真实帧间隔**喂一次 FPS；
  连续 3 秒 <32 降一级，连续 10 秒 >50 升一级（迟滞防抖）。开场 4 秒不采样；
  页面隐藏回来的大间隔（>0.5s）只重置 FPS 窗口。门槛钟用真实时间而非模拟时间
  （低帧率下模拟时间会被 dt clamp 拖慢）。渲染副作用集中在 main 的 onLevel 回调
  （pixelRatio + composer.setPixelRatio + 玻璃材质切换 + bloom 开关）。
  触屏设备（pointer:coarse）像素比上限从 2 收到 1.5（setup.js 与 quality 基准一致）。

- 渲染性能（v2.1.4，浏览器实测，格式：修复前 → 修复后）：
  - 一条 GLB 鱼的 3~4 个 SkinnedMesh 共用一份骨架（`shareSkeleton`，骨骼与逆绑定矩阵一致才合并）：
    骨骼纹理上传 经典缸 213 → 53、荷兰草缸 138 → 36 次/帧。
  - 鱼的材质克隆不再 dispose（无独占 GPU 资源；dispose 会让 three 删掉着色器程序、切回时重编译），只释放骨架；
    切场景在黑场里 `renderer.compileAsync` 预编译（上限 1.5 s）。回访场景重新链接程序 6~12 → 2~4 个；
    揭幕后最长帧 95~208 ms → 3~5 ms（首次进入的编译耗时都落在黑场里）。
  - 阴影贴图限频 30 Hz（`shadowMap.autoUpdate=false`，主循环按 `SHADOW_DT` 置 needsUpdate）：
    60 Hz 下 draw call 约 -17%（经典缸 601 → 500），刷新率越高省得越多。

    `setMSAA` 按画质档开 MSAA（像素比 ≥1.75 不开，最低档 2x，其余 4x）。

  - 自然水域岸线：`natural-shells` 烘一张水深贴图（R8，`DEPTH_MAX`=0.6），水面按水深在岸边淡出、浅滩更透、

    玻璃改为不写深度（几乎全透明，写了深度就只"看得到"前玻璃）。自然水域关闭（水面着色器已按水深处理）。调试钩子 `haze(on, k?, max?)`。

- 渲染性能（v2.2，对照学习项目 SkentSun/aquarium-editor 的 PERFORMANCE.md 第一轮优化移植）：
  - 造景物件绘制批处理 `scenes/item-batch.js`：静态小网格按「材质 uuid + 阴影标志 + 属性签名(名:itemSize 排序) + 是否索引」
    分桶，每桶 ≥2 件合成一个 `BatchedMesh`（`WEBGL_multi_draw` 多绘制，一次提交画全桶；扩展不可用则整体跳过、保持原网格）。
    原网格隐藏保留作编辑代理：编辑器进入拆批恢复逐件拾取/拖拽，退出（`apply` 之后）由 `runtime.setBatching(true)` 立即重批；
    `sync` 对"同桶同网格同矩阵"做脏检查，亲密度发鱼等频繁 `apply` 不会反复重建 GPU 缓冲。InstancedMesh（植物丛/香蒲/触手）
    本身已是单次绘制，不参与；透明/morph/多材质槽不参与（分桶键即 `bucketOf` 纯函数，Node 单测覆盖）。
  - 着色器注入加 `USE_BATCHING` 分支：`injectCaustics`（vWPos）、`injectSway`（toW/base 与 vSwW）、
    `injectFloat`（toW）在批处理下经 `batchingMatrix` 取世界坐标——焦散网纹、水流倒伏、浮叶贴浪与逐件渲染完全一致；
    three 的程序缓存键含 batching 位，共享材质在批/非批两条路径各自编译一份程序，互不污染。
  - 自动画质升级（`systems/quality.js`）：每级新增「画布像素预算」`pixels`（标定为各档像素比在 1080p 下的实际像素数）与
    「阴影刷新率」`shadowHz`（30→10 Hz）。`budgetRatio(budget,w,h,base)` = min(base, sqrt(预算/窗口像素))、下限 0.6——
    4K 大窗口立即缩像素，不再等帧率阶梯慢压；小窗口预算用不完、行为与原先一致。`reapply()` 供 resize 重发当前档。
  - 整帧渲染统计：`renderer.info.autoReset=false` + 主循环每帧手动 reset（覆盖主场景/阴影/后期全部通道）；
    `__aqDebug.perf()` 读上一帧 draw calls / 三角形 / 几何纹理数 / 像素比，`itemBatches()` / `setBatching(on)`
    可量化批处理前后收益（学习项目实测同类改造 Draw Calls -84%、提交三角形 -80%）。
  - 水面细节三件套（同为 aquarium-editor 移植，纯着色器增强不动架构）：焦散**色散**（`caustics.js` RGB 沿轴错开
    采样、随水深拉开，网纹边缘微彩虹）；水面**灯带实形反射**（`tank.js` LAMP_RECT 按各外壳发光面真实几何给出矩形，
    视线经波面反射打到灯平面命中才亮，reef 双灯盘查两块；`daynight` 用 uLampK 跟随灯具昼夜调光）；
    **弯月线**（水面贴玻璃处银线收边，自然水域随 uLampOn=0 一并关闭）。
  - **水体合成 pass**（v2.3，整体移植 aquarium-editor 的 post.js WATER_FS，水面从此"不是网格而是光线合成"）：
    - 新模块 `scene/water-pass.js`：玻璃缸的水面/水体由紧跟场景渲染的全屏 pass 合成——俯视波面折射偏移 + 菲涅尔
      混灯带/房间反射；水中按 exp(-σL) 吸收（σ 随开缸浊度加浓）+ 14 步 march **阴影图与解析焦散网纹**的灯内散射
      （光柱被石头/沉木/鱼剪影切开、HG 相函数、夜间跟随主灯变暗）；仰视水面**全内反射**显示缸内镜像（半分辨率
      平面镜像 RT，仅相机入水时渲染）；缸内看侧玻璃掠射角是**平面镜**（左右 0.55× 镜像 RT，仅相机在缸内时渲染）；
      弯月线。镜像渲染期间冻结阴影更新（复用主相机阴影图）。
    - 通道结构与深度反馈环红线：RenderPass（场景+深度→composer A）→ 水体 pass 读 A 颜色+深度、写私有 rtWater
      （needsSwap=false）→ lens 颜色源切到 rtWater（新增 `setSource`）、深度仍读 A → 泛光 → 输出。任何被采样的
      目标都不在当前绘制目标上；水面网格（缸）不写深度的老约定由此接管为"合成不写深度"。
    - 模式切换 `applyWaterMode`（main）：玻璃缸=合成+藏水面网格；自然水域=保留网格水面（岸线/浅滩/白沫依赖水深
      贴图，盒体模型做不了）；编辑器打开=全关。画质最低档 `setShafts(0)` 停 march。`__aqDebug.water(false)`
      一键回退网格水面做 A/B，`absorb(k)`/`shafts(k)` 调参。
    - 与场景水面的 uniform（uTime/uFlow/uSky/uDeep/uLamp*、浊度）全部共享引用，昼夜/款式/开缸浊度自动流入合成。

- 性能优化（v2.2.1，实测 M1 经典缸同负载 22→52 FPS、全屏尺寸阶梯收敛 45+）。逐项（按收益排序）：
  1. **镜像 RT 门控**（water-pass.js）：水面镜像只查了 y、侧玻璃镜像只查了 x，默认机位（缸外上方）
     每帧白渲 3 块镜像 = 3 次全场景重渲（~600 次蒙皮鱼绘制）。改为：水面镜像 = 水下 且 缸体 x/z 范围内；
     侧玻璃 = 相机整个在缸内。L0 绘制调用 1435→432。
  2. **同物种共享装饰材质**（school.js）：动画鱼逐鱼着色一致，材质实例 196 → 每物种 ~4 份
     （锦鲤冷暖微调与静态尾摆相位仍逐鱼克隆）。three 只在材质切换时重传 uniform，CPU 帧耗时 13.7→4ms。
  3. **光柱焦散调制贴图化**：march 每步的 2×4 迭代解析网纹（~30 次 ALU）换成 causticsTex 一次采样；
     步数随画质档 14→4（dt 同步放大，积分量不变）。单独关闭光柱的帧率差从 +13 收到 +1。
  4. **DOF 采样点数随档缩放**（lens-pass.js setTaps 24→10），单独关闭差从 +9 收到 +2。
  5. **Bloom 内部分辨率封顶 1280 宽**（setup.js 包装 setSize）。
  6. **小鱼免投影**：L<0.2 的鱼群（脂鲤/鼠鱼等）castShadow=false，阴影 pass 蒙皮绘制减半，
     三角形 1.33M→462K。
  7. **阴影刷新率下调**（quality.js shadowHz 30/24/18/12/10 → 20/16/12/10/8）：软阴影 + 慢鱼无感。
  8. **画质死区收窄**：降档阈值 32→40、升档 50→55（8 秒）。旧 33~49 死区会让 34 FPS 卡在均衡档永远不动。
  9. **倒影隔帧渲染**（water-reflect.js）：RT 里只有静态景物（鱼群本就隐藏），内容 30Hz 更新、
     采样矩阵仍每帧更新（转视角不糊）。
  10. 修复 SW 缓存版本号停在 v2.1.0：发新版后 PWA 用户会一直拿旧资产（CACHE 随版本走 v2.2.1）。
  测量方法：Chrome DevTools 实机开关矩阵（各子系统单独关闭的帧率差）+ renderer.info 逐项计数 +
  loopFrame 计时（CPU/GPU 分侧）。教训：换档瞬间有着色器重编译毛刺，帧率采样要取中位数并留稳定期。

- 阶梯防抖 + 半分辨率景深（v2.2.2，修"流畅↔均衡反复横跳"）：
  1. **震荡根因**：旧 5 级阶梯在均衡→流畅之间有像素断崖（1440×900 窗口下 2.9M→1.3M，-55%），
     升档后帧率直接砸穿降档线 → 3 秒后又降 → 无限拉锯。改为 **7 级细阶梯**（预算
     null/4.2/3.4/2.7/2.1/1.6/1.2e6，像素比闸 1.8/1.6/1.4/1.2/1/0.9），每级只差 15~25%。
  2. **升降防拉锯**：刚被降级离开的档位 45 秒冷却期内不回升（那一档已被证明带不动）；
     `force()` 清空冷却。实测 2.3 分钟 0 次换档。
  3. **底部探索**：下半区档位（level≥3）稳定 ≥50 FPS 达 30 秒且冷却已过 → 向上试一级，
     否则"够用但不到 57"的机器会永远停在最低档连 bloom 都不开。上半区不探索（保持带就是保持）。
  4. **半分辨率景深**：高清档 4M 像素下 DOF 是最大单项（交错 A/B 实测 +29 FPS——散焦像素
     24 采样点 × 每点 2 次全分辨率随机采样，带宽爆炸）。lens pass 先把颜色+深度打包降采样到

- 焦散改为实时光子泼溅（学自 tidewater `src/ocean/Caustics.js`，源自 Evan Wallace "WebGL Water"）：原来是一张随机 Voronoi 贴图两层错开滚动取 min，和水面波形无关，看上去是"图在滑"，沙面上的亮度贡献只有约 +1%。新增 `scene/caustics-gen.js`：每帧把一张周期水面 tile 的细网格画进离屏半精度 RT——顶点按波面法线折射灯光、落到 D 深处（减掉平水面偏移，图案与入射点对齐），片元写"水面面积 / 落点面积"并加法混合，即光的汇聚度（均值≈1，折叠处长出亮网纹、摊开处变暗）。

  2. **波随天气与水流**：振幅乘 `U.chop`（钳 0.35~2），相位在 CPU 双精度上取模后传入（`wavePhases`，大时间值不丢精度），水流 `U.flow` 让整片波形顺流平移，与 `waterWave` 同速。灯光方向取主灯（缸 = 顶灯，自然水域 = 斜射太阳）。
  3. **查找**（`CAUSTICS_GLSL`）：`cauRGB` 用 `textureGrad` 按像素足迹各向异性滤波（tidewater 的"最小模糊档拉伸梯度"做法，远处/掠射的底面不闪），RGB 沿光线水平方向错开一点做色散（初版错得太多，石头上成了彩虹斑，已收小到 0.001+0.0018·深度）；`cauMono` 给 tank-lens 的光柱 march 用（固定模糊档、无导数）。物件 / 沙 / 鱼的提亮统一走 `cauLift` = `max(c−0.7,0)·0.55`，仍按表面本色提亮、不压暗。
  4. **成本与开关**：每帧 2 层 × 2 焦平面共 4 次绘制（fine 约 10 万顶点、两遍共 41 万三角形）+ mip 生成；画质档 ≥3 换稀网格（`gridFor`：fine 200→128、broad 96→64，三角形约少 60%，焦散图统计不变），≥4 再隔帧更新。实测（RTX 5070 Ti，高清档）生成 GPU 0.052 ms / CPU ~0.1 ms，稀网格 0.044 ms，其中 mip 生成约 0.011 ms；整帧新旧 A/B 被显卡变频噪声淹没（同机位 1~5 ms 波动），弱 GPU 上未实测；设置里关掉焦散则整段不画。半精度 RT 不可渲染的设备退回 8 位（存 I/8，查找乘回）。`__aqDebug.caustics(layer)` 读回统计（实测 fine 均值 0.79~0.84、深焦平面暗区 54~64%）。
  5. **结果**：经典缸同机位沙面亮度 +6%、对比度 +12%（旧版 +1%）；石头顶面出现随波游走的细光纹；户外池塘斜阳下池底有清晰的水光网。

  1. **只读场景深度**（`render-scale` 的场景 RT 深度纹理；玻璃、水面不写深度，天然只遮蔽实体），法线从深度重建（左右/上下取深度差小的一侧，轮廓不连成斜面）。没用 three 的 GTAOPass——它要再画一遍法线 pass，而鱼的 VAT 蒙皮、照片鱼游动、水草摆动、浮叶都在顶点着色器里变形，覆盖材质拿不到这些变形，AO 会和画面错位。
  2. **半分辨率**（场景 RT 的一半）按切片找两侧地平线、余弦加权闭式积分；世界半径 0.28（随视深换成像素，近景封顶 48 px），超出半径的样本渐隐回"无遮挡"，前景与背光幕之间无黑晕。**薄遮挡物补偿**（XeGTAO 的 thickness heuristic，`uThin` 2.5）：渐隐距离里放大视深方向的差——第一版 IAPLC 草毯被细草叶互相遮成一片黑，加上后草毯只在根部略暗，石缝与苔藓下的接触阴影保留。
  3. **去噪**：没有 TAA，不能靠时间累积；噪声用 4×4 Bayer 固定图样（切片角 + 步进偏移），再做 4×4 深度感知盒式模糊正好把图样抹平。
  4. **合成**：放在 `edge-aa.js` 的 FXAA 收尾处乘上（`mix(1, ao, k)`，k = 0.9），不多一遍全屏 pass；因此 AA 关的最低两档也没有 AO。切片/步数按画质档 `AO_TIERS`（3×6 → 2×4）。`__aqDebug.ao(k, { uRadius, uPower, uMaxPx, uThin })` 调参。
  5. **结果**：经典缸叶丛内部、石头与沙交界、沉木脚下更有体积；苔石山石柱之间的缝隙与苔藓团下方出现接触阴影；户外池塘松树底部与岸边略暗、远景无黑晕。成本（RTX 5070 Ti，场景 RT 870×653）约 0.02 ms/帧。

- 下行光程吸收（水深渐变）：tank-lens pass 原来只按"视线在水里走了多远"吸收（`exp(-σL)`），光从水面照到物体那一段没算——缸底的沙、石脚、底层鱼和贴着水面的叶子同样暖、同样亮，整缸没有"越深越青、越暗"的纵深。`water-pass.js` 在视线吸收之前，对落在水体盒内的命中点再乘 `exp(-σ·(waterY − P.y)·uLightAtt)`：σ 与视线吸收同一个（随开缸浊度、「水色浓淡」滑杆和「水体雾化」开关联动，雾化关则两段一起关），红光衰得最快，越往下越偏青、越暗。
  1. **倍率**：`LIGHT_ATT` = 0.9（相对视线吸收系数）。试过 1.3：苔石山缸的底砂整片发青灰、失去暖色；0.9 时上层鱼保持暖橙、底层鱼与砂面略冷，石柱自上而下有一层自然的明暗过渡。
  2. **范围**：只对水体盒内的命中生效（`tSc <= th.y`），缸外的柜子、背景幕不受影响；自然水域（`setWaterOn(false)`）整段不走。零额外采样，成本可忽略。`__aqDebug.lightAtt(k)` 调倍率（0 = 关）。
